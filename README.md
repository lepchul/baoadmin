# Bao Admin 1.0

Telegram-бот для модерации групп с админ-консолью в личке. Самостоятельный проект с основными функциями в духе Iris, а не копия всех его сервисов. Работает через официальный Bot API. Session String, API_ID, API_HASH и платный AI API не нужны.

## Запуск на BotHost или другом Python-хостинге

1. Создай отдельного бота у @BotFather через `/newbot`. Имя: Bao Admin. Username выбери свободный, с окончанием `bot`.
2. Загрузи содержимое папки `bao-admin` в корень проекта хостинга.
3. Выбери Python 3.12. Установка: `pip install -r requirements.txt`. Запуск: `python bot.py`.
4. Добавь переменные окружения `BOT_TOKEN` и `OWNER_IDS`. В `OWNER_IDS` укажи свой числовой Telegram ID. Несколько владельцев можно перечислить через запятую.
5. Для локального запуска скопируй `.env.example` в `.env` и заполни значения. Не публикуй токен.
6. Для базы укажи `DATABASE_PATH` на постоянном диске. По умолчанию: `data/bao_admin.sqlite3`. Данные должны сохраняться после перезапуска и обновления проекта.
7. Добавь бота администратором в супергруппу. Выдай права удаления сообщений, блокировки участников и закрепления сообщений.
8. Напиши `/admin` в группе, нажми кнопку перехода в личку и Start. Затем выбери нужные настройки.

Один токен = один работающий процесс. HTTP-порт не нужен, используется long polling. Если у токена уже настроен webhook, останови старое приложение и отключи webhook перед запуском. Бот не удаляет его сам.

Администратор-бот получает обычные сообщения группы. Если бот не видит сообщения, проверь его статус администратора и privacy mode в BotFather. Каналы и личные аккаунты от имени группы не модерируются этим проектом.

## Docker

```bash
cp .env.example .env
# Заполни BOT_TOKEN и OWNER_IDS
docker compose up -d --build
docker compose logs -f --tail=100
```

База хранится в томе `bao-data`. Не удаляй том при обновлении.

## Админ-консоль

Команда `/admin` в личке показывает группы, в которых пользователь сейчас администратор. При каждом нажатии и сохранении права запрашиваются заново у Telegram. Старые кнопки не сохраняют доступ после снятия админки. Владелец бота не получает автоматического права модерировать чужие группы.

Для каждой группы доступны:

- включение и отключение автоматических функций;
- приветствия новых участников;
- антифлуд;
- запрет ссылок, включая скрытые ссылки и ссылки после редактирования сообщения;
- лимит предупреждений и длительность мута за них;
- число сообщений, окно антифлуда и длительность мута;
- редактор восьми текстовых шаблонов с предпросмотром;
- отдельный каталог премиум-эмодзи;
- журнал последних 15 действий и проверка прав бота.

Изначально приветствия, антифлуд и запрет ссылок выключены. Антифлуд по умолчанию: мут на 10 минут за 6 сообщений в течение 10 секунд. Предупреждения: после третьего мут на 60 минут. После успешного мута счётчик варнов сбрасывается. Если Telegram отклонил мут, варны остаются.

Выключатель группы отключает приветствия, правила, жалобы и автоматическую модерацию. Ручные команды администраторов, справка, получение ID и админ-консоль остаются доступны.

## Команды модерации

Используй команду ответом на сообщение участника. Без ответа можно указать числовой ID первым аргументом. Наказания по `@username` не поддерживаются: Telegram не позволяет надёжно разрешать произвольные usernames пользователей через Bot API.

| Команда | Действие |
| --- | --- |
| `/warn причина` | Предупреждение |
| `/warns` | Число предупреждений |
| `/unwarn` | Сброс всех предупреждений участника |
| `/mute 30m причина` | Мут на 30 минут |
| `/mute 123456789 2h флуд` | Мут по ID на 2 часа |
| `/unmute` | Вернуть стандартные разрешения группы |
| `/ban причина` | Бессрочный бан |
| `/unban` | Разрешить повторный вход, без автоматического возврата |
| `/del` | Удалить сообщение, на которое дан ответ |
| `/pin` | Закрепить сообщение из ответа |
| `/unpin` | Открепить сообщение из ответа |
| `/rules` | Правила группы |
| `/report причина` | Жалоба ответом на сообщение, с упоминанием админов |
| `/id` | ID чата и автора сообщения из ответа или свой ID |
| `/emojiid` | ID премиум-эмодзи |
| `/cancel` | Отменить ввод в консоли |

Короткие русские команды: `бан`, `разбан`, `мут`, `размут`, `варн`, `пред`, `преды`, `снятьпреды`, `правила`, `репорт`, `админ`. Пример: `мут 30м флуд` ответом на сообщение.

Сроки: `m/м` минуты, `h/ч` часы, `d/д` дни. Допустимо от 1 минуты до 365 дней. Муты работают в супергруппах. Срок отслеживает Telegram, поэтому перезапуск бота не продлевает наказание.

Для наказаний администратору нужны права ограничения участников. Для удаления и закрепления проверяются соответствующие права. Себя, Bao Admin и администраторов наказать нельзя. Команды от анонимных администраторов или имени каналов не выполняются: отправляй их от своего аккаунта.

Антифлуд и фильтр ссылок не применяются к администраторам. Счётчики короткого окна антифлуда и лимит жалоб находятся в памяти и сбрасываются при рестарте. Варны, настройки, тексты, эмодзи и журнал сохраняются в SQLite.

## Премиум-эмодзи

### Получить ID

Отправь боту сообщение с премиум-эмодзи. Ответь на него:

```text
/emojiid
```

Бот извлекает `custom_emoji_id` всех найденных эмодзи, включая подписи к медиа. Обычный Unicode-эмодзи такого ID не имеет. Команда не превращает обычные стикеры в премиум-эмодзи.

### Добавить в каталог

Открой `/admin`, выбери группу, затем «Каталог эмодзи» и «Добавить». Отправь имя и ID:

```text
bao 5368324170671202286
```

ID выше только пример из документации. Используй ID нужного тебе эмодзи. Вместо ID можно отправить имя и сам премиум-эмодзи. Бот проверит ID через Telegram и сохранит стандартную эмодзи-замену.

То же самое командой в личке после выбора группы:

```text
/emoji add bao 5368324170671202286
/emoji list
/emoji del bao
```

До удаления нужно убрать вставки этого эмодзи из шаблонов. В группе можно сохранить до 40 имён.

### Вставить в разные предложения

В консоли открой «Тексты и эмодзи», выбери текст и отправь новый вариант:

```text
{emoji:bao} {user}, добро пожаловать в {chat}!
Прочитай /rules и устраивайся поудобнее
```

Или командой:

```text
/text warn {emoji:bao} {user}, предупреждение {count}/{limit}. Причина: {reason}
```

Можно вставлять премиум-эмодзи непосредственно в сообщение редактора, без каталога. Их ID сохраняются с учётом UTF-16 смещений Telegram, в том числе рядом с обычными эмодзи.

Ключи текстов: `welcome`, `rules`, `warn`, `mute`, `unmute`, `ban`, `unban`, `unwarn`.
Вставки: `{user}`, `{chat}`, `{admin}`, `{reason}`, `{count}`, `{limit}`, `{duration}`, `{emoji:имя}`. Счётчик и лимит заполняются в предупреждении, срок в сообщении о муте. Неприменимые поля пустые. Текст до 1500 символов, HTML вводить не нужно. Имена, причины и текст экранируются. Длинные тире автоматически заменяются на обычный дефис.

По текущим правилам Telegram кастомные эмодзи в сообщениях бота разрешены при Telegram Premium у владельца бота либо при купленном дополнительном username на Fragment. Одного ID недостаточно. Если Telegram вернёт ошибку отправки такого текста, бот попробует обычную эмодзи-замену. Некоторые клиенты сами показывают замену.

Источник: https://core.telegram.org/bots/api#html-style

## Дополнительные настройки

В личке после выбора группы:

```text
/limits 3 60 6 10 10
```

Порядок: лимит варнов, мут за варны в минутах, сообщений за окно, окно в секундах, мут за флуд в минутах. Всё это доступно и через кнопку «Лимиты».

Только владельцы из `OWNER_IDS` могут включить общий режим техработ:

```text
/maintenance on
/maintenance off
```

Он приостанавливает автоматическую модерацию и приветствия. Ручная модерация остаётся для админов, `/rules` и `/report` в этот период доступны только админам. Справочные команды и ID остаются доступны всем.

## Проверки и ограничения

Запуск тестов из папки проекта:

```bash
pip install -r requirements.txt
python -m unittest discover -s tests -v
```

Проверены доступ обычных участников, актуальность прав на кнопках, защита админов, сроки мутов, порог предупреждений, обработка отказа Telegram, разбан, права после размута, скрытые и отредактированные ссылки, флуд командами, каталог и замена эмодзи, UTF-16, сохранение и изоляция групп.

Тесты используют подмену Telegram API. Живой запуск с токеном и реальной группой не выполнялся. После запуска проверь `/admin`, `/emojiid` и мут тестового участника в своей тестовой группе.

Сетевые изменения не повторяются автоматически после таймаута: Telegram мог успеть применить действие. В таком случае сначала проверь состояние участника. Update ID сохраняется перед обработкой, поэтому авария в середине команды может привести к её неполному выполнению, но не к автоматическому повторному наказанию при рестарте.

В архиве нет токенов и готовой базы участников. Бот не сохраняет полную переписку. В журнале остаются ID админа и участника, действие и указанная причина. Резервную копию базы делай при остановленном процессе или штатным механизмом SQLite backup.

Не входят: экономика, игры, репутация, пользовательские ранги Iris, капча, веб-панель и глобальная база нарушителей.
